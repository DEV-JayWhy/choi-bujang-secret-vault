## 핵심 기능 3가지 시연 순서

아래는 **실제 브라우저에서 실행할 때의 예정 순서와 대본**입니다. 이번에는 브라우저 시연·사용자 PC 연습을 수행하지 않았습니다. 대신 같은 앱 커밋에서 모의 DOM과 로컬 API 순서를 실행했습니다. 화면을 보여 주었다고 기록하지 않습니다.

| 순서 | 동작과 보여 줄 내용 | 설명 대본·구분 기준 |
|---|---|---|
| 1 · 계정·기기·세션 (약 1분) | 기본 npm start → 보호 현황의 내 정보 학생 영역 → 네 카드와 다시 조회·대기·실패 안내 | “로컬 앱은 켜졌지만 SDP는 미연결입니다. 확인 불가를 정상으로 바꾸지 않습니다. 다시 조회는 이 학생 영역만 갱신합니다.” |
| 2 · 보안 기록 (약 1분) | 기본 서버 종료 → npm run demo → 보안 기록 → 예시 표시 확인 → 필터·사건 상세 | “여기는 예시 보안 기록입니다. 선택한 사건의 ID·근거·규칙을 보여 줍니다. 실제 XDR 탐지·학생 계정 연결 성공이 아닙니다.” |
| 3 · 설치 패키지 조회 (약 1분) | 보호 현황의 설치 패키지 학생 영역 → 다시 조회 → not_configured와 이유 확인 | “현재 조회 대상 프로젝트 설정이 없습니다. 취약점 없음이 아닙니다. 설정이나 허용 목록을 임의로 바꾸지 않았습니다.” |

제공 PC 카드는 별도로 소개합니다. “여기에는 서버 실행 컴퓨터의 값과 측정 시각이 표시됩니다. demo의 보안 기록은 예시지만 PC 조회는 별도 실제 수집 경로입니다. 현재 자료의 실측 대상은 AI Linux 환경이며 제 Windows PC가 아닙니다. Windows 경고·오류 건수는 침해 또는 공격 탐지 결과가 아닙니다.”

AI 승인·유료 설명 요청·보안 조치 집행·외부 OSV 조회는 시연 연습에 포함하지 않았습니다. 성공처럼 보이기 위해 예시 값으로 대체하거나 의존성을 낮추지 않습니다.

## 같은 결과를 다시 확인하는 순서

지금 사용자가 실행할 의무는 없습니다. 나중에 실행한다면 기존 작업을 보존한 새 폴더에서 같은 기준 커밋을 받고, Git·Node.js·npm 설치를 확인합니다. Windows 절대 경로는 확인하지 않아 임의로 기입하지 않습니다. 세부 실행·오류·R7 절차는 [STUDENT_RUNBOOK.md](STUDENT_RUNBOOK.md)를 따릅니다.

앱 실행은 **저장소 안 on-client 폴더**에서 합니다.

```powershell
node --version
npm --version
npm run check
npm start
```

1. 시작 로그 `케셰브 연결 확인: http://127.0.0.1:5189`를 확인하고 브라우저에서 `http://127.0.0.1:5189/`를 엽니다. 서버 시작은 SDP 연결 성공이 아닙니다.
2. 위 시연 1번을 확인합니다. 제공 「내 PC 상태」 버튼으로 조회했다면 해당 컴퓨터의 source·측정 시각·단위·확인 불가 이유를 확인합니다. 관리자 권한 요청·보안 설정 변경은 하지 않습니다.
3. Ctrl+C로 종료하고 `npm run demo`로 예시 보안 자료를 봅니다. 위 시연 2·3번을 진행하며 실제와 예시를 항목별로 구분합니다.
4. Ctrl+C 후 `npm start`로 기본 실행으로 돌아갑니다. 브라우저 탭만 닫아서는 서버가 종료되지 않습니다.

자동 검사 기록은 **Git 최상위 폴더**에서 아래 명령으로 만듭니다. 출력 JSON은 프로젝트 밖의 아직 없는 새 파일이어야 하며 기존 근거를 덮어쓰지 않습니다.

```powershell
node docs/verify-final.mjs --output ../keshev-evidence/day7-new-run.json
```

나중에 Windows에서 PC 원천 응답만 확인하려면 실행 중인 로컬 서버에 아래 읽기 전용 명령을 사용할 수 있습니다. 출력의 측정 대상은 그 서버의 컴퓨터이며 이번 문서의 Linux 값과 같을 필요가 없습니다.

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:5189/api/pc/status | ConvertTo-Json -Depth 8
```

이번에는 포장 명령을 실행하지 않습니다. 향후 실제 포장은 공식 R7 준비와 256×256 PNG·커밋·새 출력 경로를 확인한 뒤 제공 PACKAGE_APP.md를 따릅니다. 생성한 INSTALL.md의 실제 해시와 명령으로 설치하고 승인 host 바로가기를 확인한 경우에만 패키지 경로와 실행 근거를 추가합니다. 제출·유료 요청·실제 집행은 별도 사용자 지시 없이 수행하지 않습니다.
