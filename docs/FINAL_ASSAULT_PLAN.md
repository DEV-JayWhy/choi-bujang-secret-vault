## 제공 기능과 현재 버전의 차이

2026-10-26 원문을 대조했습니다. 현재 앱 0.2.11에는 CPU·메모리·디스크 수집 모듈·API·학생 입력 계약이 없고, `student/appearance.json`과 `package-app` 명령도 없습니다. 확인한 공식 0.2.14 시작 틀에도 이 기능과 명령은 없었습니다. 따라서 0.2.14를 받았다는 이유만으로 필요한 기능이 준비됐다고 판단하거나 자동 적용하지 않습니다.

공식 마지막 총공세 안내는 제공된 「내 PC 상태」가 있으면 중복 구현하지 말라고 안내합니다. 포장 명령이 없는 이전 시작 틀은 담당자에게 학생 파일을 보존하는 제공 파일 업데이트를 요청하도록 명시합니다. 새 포장 스크립트를 만드는 방식으로 대신하지 않습니다.

| 구분 | 제공 측에서 확인할 것 | 학생이 개선할 것 |
|---|---|---|
| PC 측정 | 일반 권한의 실제 수집 기능, 출처·단위·측정 시각·실패 이유를 전달하는 계약 | 전달받은 값의 직전/현재 비교와 설명 |
| 학생 화면 | 설치형 앱이 실제 반영하는 학생 확장 진입점 | 기존 `student/extension.mjs`에서 표시 확장 |
| 꾸밈 | 선택 사항인 `student/appearance.json`의 실제 지원·허용 속성 | 허용 범위에서 관제 대시보드 배치 |
| 포장 | 기존 `package-app` 도구와 승인 실행 환경·설치 절차 | 제공 명령 실행 결과·manifest·바로가기 확인 |

`public/app.js`·`public/style.css` 수정 결과가 설치형 앱에도 반영된다고 가정하지 않습니다. 학생 기능을 연결할 실제 입력 계약이 확인될 때까지 함수를 새로 만들어 연결됐다고 표시하지 않습니다. 앞 계획의 수집기·포장 스크립트 신규 작성과 public 파일 중심 변경은 이 정정으로 보류합니다.

## 다듬을 핵심 기능 3가지

| 순서 | 핵심 기능 | 계획한 결과 | 확인 기준 |
|---|---|---|---|
| 1 | 제공 PC 상태를 이용한 카드 네 개 | CPU·메모리·디스크·최근 조회 상태와 측정 시각 표시 | 제공 수집 기능 확인 후 재사용. 권한 부족·미지원·실패는 확인 불가 |
| 2 | 직전 실측과 현재 실측 비교 | 하단에 직전/현재 값·변화량·조회 기록 표시. 이번 학생 개선 한 가지로 선택 | 동일한 측정 대상·지표·단위의 실제 샘플만 비교. 두 유효 값이 없으면 비교 불가 사유 표시 |

이번 PC 상태 개선은 일반 권한으로 읽는 CPU·메모리·디스크와 조회 상태를 대상으로 합니다. 관리자 권한 요청·승격이나 방화벽 설정 변경·차단·해제는 사용하지 않습니다. 현재 합의한 포장은 기본 포장이며 setup.exe는 이번 목표에 포함하지 않습니다.

## 실측값·예시값·확인 불가 표시 원칙

| 구분 | 화면에 표시할 내용 | 처리 원칙 |

| 실제 조회 | `실제 조회`, 측정 대상·출처·시각·단위 | 앱 서버가 실행되는 컴퓨터에서 얻은 값만 표시. AI 실행 환경의 값을 사용자 PC 값이라고 쓰지 않음 |
| 예시 | `예시 · 실제 조회 결과 아님` | 화면과 설명에서 계속 구분. 실제 기록·추이와 섞지 않음 |
| 확인 불가 | 확인 불가와 이유·조회 시각 | 권한·미지원·시간 초과·실패를 정상이나 0으로 바꾸지 않음 |

## 직전/현재 비교 표시 규칙

- CPU는 사용률 `%`와 변화량 `%p`를 구분합니다. 메모리 사용량·디스크 남은 공간은 제공 단위를 명시하며, 표시용 변환을 하면 변환 단위를 함께 적습니다.
- 각 값에 실제 측정 시각을 붙입니다. 요청한 시각이나 화면을 그린 시각을 측정 시각으로 바꾸지 않습니다.
- 이전/현재 두 값의 측정 대상·출처·단위가 맞지 않거나 값이 하나뿐이면 비교하지 않고 그 이유를 표시합니다. 예전 값을 현재 값으로 재사용하지 않습니다.
- 실패 항목은 `확인 불가`와 제공된 안전한 이유를 표시합니다. 측정하지 못한 시각은 측정 시각 확인 불가로 구분합니다.
- 예시값은 별도 예시 영역에서만 사용하며 실제 비교·기록에 섞지 않습니다. 단순 증가/감소를 보안 정상·위험 판정으로 단정하지 않습니다.

## 현재 앱을 다시 실행하는 순서

사용자의 기존 프로젝트 안 `on-client` 폴더에서 PowerShell을 엽니다. 사용자의 Windows 절대 경로는 아직 확인하지 않았으므로 임의 경로를 실제 경로로 적지 않습니다.

```powershell
node --version
npm --version
npm run check
npm start
```

1. `케셰브 연결 확인: http://127.0.0.1:5189` 시작 메시지를 확인합니다. 이는 로컬 서버 시작이며 실제 엔진 연결 성공이 아닙니다.
2. 브라우저에서 `http://127.0.0.1:5189/`를 엽니다. 기본 미연결 상태를 정상 데이터로 오해하지 않습니다.
3. 예시 자료를 보려면 실행 창에서 `Ctrl+C`로 종료하고 같은 폴더에서 `npm run demo`를 실행합니다. 자료가 예시임을 확인합니다.
4. 기본 실행으로 돌아가려면 `Ctrl+C` 후 `npm start`로 다시 켭니다. 현재 앱 폴더는 외부 npm 의존성이 없어 기본 실행에 별도 의존성 설치가 필요하지 않습니다.

사용자가 지금 당장 직접 실행해야 다음 개발이 가능한 것은 아닙니다. 코드·검사·GitHub 반영은 AI 작업 환경에서 진행할 수 있습니다. 다만 사용자 PC 실측값, Windows 일반 권한의 실제 조회, 실제 브라우저 조작, 바로가기 실행은 마지막에 사용자 PC에서 별도로 확인해야 합니다. 그때 필요한 순서를 한 번에 하나씩 안내하고 실행하지 못한 항목은 미확인으로 남깁니다.

## 네트워크·방화벽·Windows 기록 조회 확장 계획

2026-10-26 추가 요청입니다. 기존 CPU·메모리·디스크 계획과 앞 단계 기능을 보존하고, 네트워크·Windows 상태 영역에 카드 네 개와 하단 조회 기록·비교를 구성합니다. 이 절은 구현 계획이며 실제 사용자 PC 조회 결과가 아닙니다.

현재 저장소 앱에는 네트워크 구성·Windows 방화벽·System/Application 기록 수집 기능과 해당 학생 입력 계약이 없습니다. 먼저 제공 업데이트의 실제 수집 경로·안전한 오류·입력 계약·설치형 반영 범위를 확인합니다. 임의 API나 학생 함수 이름을 만들어 연결됐다고 쓰지 않습니다.

| 카드 | 표시 범위 | 출처·시각·실패 처리 |
|---|---|---|
| 네트워크 구성 | 인터페이스, IP, 기본 게이트웨이, DNS | 일반 권한에서 읽힌 값과 조회 시각. 항목별 실패는 확인 불가와 안전한 이유 |
| 방화벽 설정 | 프로필별 사용 상태 | 읽기만 수행. 조회 시각과 출처 표시. 읽기 거부는 확인 불가이며 방화벽 꺼짐으로 바꾸지 않음 |
