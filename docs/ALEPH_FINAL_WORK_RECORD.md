- 잘못된 입력이나 연결 실패 때의 동작: 학생 직접 확인 미확인. 코드·모의 검사에서 실패 항목과 다음 행동을 표시하고 예시값·이전 성공값으로 대체하지 않도록 확인했습니다. PC 조회 성공과 SDP 미연결은 구분합니다.

## 3. 값의 종류 구분

- 실제 조회(내 PC 실측 또는 서비스 API 결과와 출처·조회 시각): **학생 PC 실측은 미확인.** 별도 AI Linux 환경의 제공 GET /api/pc/status 조회에서 CPU·메모리·디스크 값을 실제로 읽었습니다. source는 local-pc, 측정 시각은 2026-10-26 14:39:46.338(KST)입니다. CPU는 %·200ms 표본, 메모리·디스크 원천 단위는 bytes입니다. 이 환경의 값은 학생 Windows PC 값이 아닙니다. [PC 조회 기록](evidence/day7-pc-check.json)에 지표별 값·단위·시각을 보존했습니다.
- 설명용 예시(실제 조회 결과가 아닌 값): npm run demo의 계정·기기·세션·보안 기록, 모의 DOM 검사의 사건·패키지·AI 설명 자료. demo 보안 자료와 제공 PC API의 실제 수집은 서로 다른 경로입니다. 포털의 안내 그림도 앱 실행 증거가 아닙니다.
- 미연결(예: SDP 서버에 연결되지 않은 항목): 기본 실행의 계정·기록 API는 ENGINE_NOT_CONNECTED·disconnected. 실제 SDP/XDR·AI 연결은 미확인입니다. PC 값을 읽었다고 계정 연결 완료로 적지 않습니다.
- 확인 불가(읽지 못한 값과 그 이유): 이번 AI Linux 환경에서 네트워크 query_failed, Windows 방화벽·기록 unsupported. 일반 권한 조회 실패·미지원은 확인 불가이며 0·정상·안전으로 대체하지 않습니다. Windows 경고·오류 건수는 침해·공격 탐지 결과가 아닙니다.

## 5. 처음 사용한 사람이 막힌 곳

- 다른 사람의 첫 사용 관찰 여부: **미실시.** 부탁할 사람이 없어 실제 동료 테스트를 하지 않았습니다.
- 막힌 위치: 다른 사람이 보고한 막힘은 없습니다. AI 대체 점검으로 저장소 최상위에서 npm run check를 실행하는 상황을 골랐고 Missing script: "check" 오류를 재현했습니다.
- 내가 보완한 것: AI 도움으로 실행 설명서 맨 앞에 앱 이름 alekov-client-starter와 on-client 작업 위치 확인을 포함한 한 장 안내를 추가했습니다. 코드 오류로 단정해 앱을 바꾸지 않았습니다.
- 다른 사람이 보완 뒤 다시 따라 해 본 결과: **미실시.**
- 내가 직접 보완 뒤 다시 실행한 결과: **학생 직접 실행 미확인.** AI가 당시 Linux 작업본에서 올바른 on-client의 검사·실행·HTTP 응답·종료·재실행을 확인했습니다. 이 대체 점검을 동료 관찰로 적지 않습니다. 당시 5일차 기록과 현재 0.2.19 근거는 버전을 구분합니다.
- 근거: [실행 설명서의 5일차 대체 점검 기록](STUDENT_RUNBOOK.md). 원래 폴더·학생 코드·제출물을 보존했습니다.

- 그중 내가 고르거나 바꾼 것: setup.exe 대신 기본 포장과 바로가기를 선택했습니다. 제공 PC 조회를 재사용하고 중복 수집기·새 포장기를 만들지 않기로 했습니다. 사용자 PC 설치·실측은 이번에 생략하고 미확인으로 남기기로 했습니다. 예시를 실측이나 연결 성공으로 표현하지 않기로 했습니다.
